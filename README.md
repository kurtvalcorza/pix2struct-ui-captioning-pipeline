# Pix2Struct widget-captioning-base UI widget captioning pipeline

DIMER inference and fine-tuning wrapper for **Pix2Struct fine-tuned on Widget Captioning** (`google/pix2struct-widget-captioning-base`), Google Research's 282M-parameter image-encoder/text-decoder that describes one UI element on an app screenshot in a short phrase (`search bar`, `go to profile`) — the target widget is indicated by a blue box drawn on the screenshot, exactly as the upstream preprocessing did — pinned to an immutable Hugging Face revision and loaded only from a digest-verified local snapshot. The pipeline accepts one screenshot and one widget box in pixels, draws the box itself, decodes greedily under a caller-owned token budget, and returns the caption string with a `truncated` flag; it returns no score and locates nothing, and it renders no header text, so no font is fetched from the Hub at inference time. It also carries a bounded adaptation contract: `adapt` fine-tunes the caption decoder's last blocks and final layer norm on a validated `{id, image, box, captions}` dataset, `evaluate` scores a held-out split with BLEU-4, ROUGE-L, CIDEr-D and unigram F1 beside two non-neural baselines, and `save_artifact` / `from_artifact` export and reload the trained tensors as a safetensors adapter bound to the pinned base.

## Upstream alignment

- Model: `google/pix2struct-widget-captioning-base`
- Revision: `7e99642f87127dd3aee97ea82616bbfda5e610bb`
- Upstream weight license: Apache-2.0
- Upstream task: widget captioning (Rico screenshots, Li et al. 2020)
- Repository adaptation: bounded supervised fine-tuning of the caption decoder's last *k* blocks plus its final layer norm (`adapt`; the image encoder, embeddings and untied `lm_head` stay frozen; the snapshot's `is_vqa` header path is disabled to match the upstream preprocessing, see `docs/WEIGHTS.md`); the tutorial's default corpus is one shard of Widget Captioning test widgets (`bevaya/RICO-WidgetCaptioning` @ `6ec57b56bebd722b9c646c78d0f34e1199b6d7a9`, CC BY 4.0), downloaded whole at run time and refused unless its SHA-256 matches the pin recorded by `tools/pin_corpus.py`

## Quick start

```python
from PIL import Image
from pix2struct_ui_captioning_pipeline import Pix2StructWidgetCaptioningPipeline, annotate_widget

pipe = Pix2StructWidgetCaptioningPipeline.from_pretrained()        # stages + verifies weights/pix2struct-widget-captioning-base first
result = pipe.caption(Image.open("screen.png"), [90, 820, 450, 880])   # box = [x0, y0, x1, y1] in pixels
print(result["caption"], result["new_tokens"], result["truncated"])   # generated text; no score exists

annotate_widget(Image.open("screen.png"), [90, 820, 450, 880]).save("screen_boxed.png")   # what the model saw
```

Install into a Python 3.12 environment that already holds the pinned dependencies with `pip install -e . --no-deps`; run `pytest -q -o addopts= tests` for the offline test suite (no weights needed). On a fresh clone the manifest is committed but the weights are not: `Pix2StructWidgetCaptioningPipeline.from_pretrained(allow_download=True)` fetches exactly the missing manifest-listed files at the pinned revision, then verifies them.

## Weights layout

```
weights/pix2struct-widget-captioning-base/
  dimer-base-manifest.json   # modelId, revision, per-file bytes + SHA-256 (8 files)
  config.json                # Pix2StructForConditionalGeneration: 12-layer ViT encoder + 12-layer text decoder
  preprocessor_config.json   # is_vqa: true (header path disabled by this package), max_patches 2048, 16x16 patches
  special_tokens_map.json  spiece.model  tokenizer.json  tokenizer_config.json
  model.safetensors          # git-ignored, 1,129,177,976 bytes
  README.md
```

`pytorch_model.bin` exists upstream and is deliberately not listed (pickle; DIMER does not accept `.bin`).

## Input ceilings and request parameters

`MIN_IMAGE_SIDE = 16`, `MAX_IMAGE_SIDE = 4096`; the box is `[x0, y0, x1, y1]` in pixels inside the image with sides of at least `MIN_BOX_SIDE = 4`; `BOX_COLOR = (0, 0, 255)`, `BOX_WIDTH = 3`; `MAX_NEW_TOKENS = 64`, `DEFAULT_MAX_NEW_TOKENS = 20`; `DECODING = "greedy"`; `MAX_PATCHES = 2048` (the processor's patch budget, documentation only). See `MODEL_CARD.md` for who owns the budget and the box, why the report is `not-measurable` without references, and the measured CPU timings.

## Tutorials

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/kurtvalcorza/pix2struct-ui-captioning-pipeline/blob/main/tutorials/pix2struct_ui_captioning_colab.ipynb)

`tutorials/pix2struct_ui_captioning_colab.ipynb` is declared `E2E` / `GUIDED` under DIMER Notebook Specification 2.0 and is **standalone** (§4): generated by `tools/build_notebook.py`, it carries the three pipeline modules (`pipeline.py`, `metrics.py`, `samples.py`), model identity, manifest digests and runtime pins, so the exported notebook runs without this repository (parity enforced by `tests/test_notebook_parity.py`). Its default `Run all` path resolves the pinned model through the carried staging and verification path, downloads one digest-pinned shard of Widget Captioning test widgets and splits a seeded subset of whole apps into about 320 / 64 / 160 training, validation and test widgets, captions five boxed widgets on a drawn messaging-app screen through `validate_inputs` and `caption` with keyword observations, scores the frozen model on the test widgets beside the constant-caption and colour-nearest-neighbour baselines (BLEU-4, ROUGE-L, CIDEr-D, unigram F1, per `small-widget` / `large-widget` category), fine-tunes the caption decoder's last two blocks and final layer norm with validation-CIDEr-D epoch selection, scores the held-out widgets again (the gain is recorded as `adapted_beats_frozen`, not asserted), re-captions the drawn screen, and exports a safetensors adapter that it reloads with verified parity — one seeded split of one shard, no benchmark claim. BYOD (one zip of screenshots plus `records.jsonl`) is optional and gated off by default. See `tutorials/README.md` for the registry and `docs/release-verification.md` for the release gate.
