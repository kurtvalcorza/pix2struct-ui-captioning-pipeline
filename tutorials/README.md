## Conformance notes

- **Standalone carrier (NOTEBOOK_SPEC 2.0 §4):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/pix2struct_ui_captioning_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 8-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the generating revision, the module's SHA-256, and the generator version.
- **Parity (PAR1–PAR3):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD8):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry; `from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files with `local_files_only=True` and `trust_remote_code=False` through `Pix2StructForConditionalGeneration`/`Pix2StructProcessor` and disables the snapshot's `is_vqa` header path (the upstream preprocessing drew a blue box and no header), so **no font is fetched at inference time**. The upstream `pytorch_model.bin` is not listed and not used; the notebook's only external dependencies are the pinned PyPI distributions and the Hub at the model revision.
- **Role stages:** `validate_inputs` writes `outputs/pix2struct_ui_captioning_input_manifest.json` with the schema (box rendering, patch budget, decoding rule), the ceilings, the input's observed mode and size, the checked boxes, the budget, the verdict, and one recorded rejection finding from the box-outside-image probe; `evaluation_report` writes `outputs/pix2struct_ui_captioning_evaluation_report.json` — `not-measurable` on the default path (no reference captions exist; the keyword observations are attached under `observations` and are not a metric), `sample-sanity` with one `unigram_f1` entry per widget only when the learner supplies references (stated as bag-of-words overlap, not CIDEr/BLEU).
- The default sample is a deterministic 540×960 messaging-app mock drawn in code with Pillow's bundled font — the same mock the smoke run used; no reference captions are authored because a caption the author writes is not an annotation standard, so the report is `not-measurable` **by design** (the fleet matrix lists this row as report-only) and the keyword checks (`message`, `search`, `settings`, `ana`, `profile`) are observations the learner can verify by eye. The smoke run's miss (`go to next` for the gear icon) is recorded in the notebook prose. The image digest depends on the Pillow build's bundled font rendering and is printed, not asserted.
- Score semantics (UNC1–UNC4): the caption is generated text with no score, probability or correctness signal; the notebook says so before the first caption and again in the interpretation section, states that the box is part of the request, and states that the model captions boxes that enclose nothing (blank image → `select the image` in the smoke run). The token budget is a caller-owned request parameter exposed as a `# @param` value (default `DEFAULT_MAX_NEW_TOKENS = 20`) and passed explicitly on every `caption` call; `truncated` is surfaced and explained. The notebook performs no validation of its own — image, boxes and budget are checked only by the pipeline's `validate_inputs`/`caption` path.
- Ceilings `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4096), `MAX_PATCHES` (2048), `MIN_BOX_SIDE` (4), `BOX_COLOR`, `BOX_WIDTH` (3), `MAX_NEW_TOKENS` (64), `DEFAULT_MAX_NEW_TOKENS` (20) and `DECODING` are printed before the model runs.
- CPU is documented as adequate (card-measured 5.4 s load, 2.0–2.4 s per widget on the 540×960 mock; 2.7 s for a box on a 4096×4096 blank image); the notebook states that cost is per widget and that GPU output need not match CPU output token-for-token.
- `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.
