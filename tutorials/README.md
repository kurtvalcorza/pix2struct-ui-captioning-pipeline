## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`) captioned five boxed widgets on a drawn messaging-app screen and reported keyword observations with a `not-measurable` evaluation report, because no reference captions were bundled. This notebook keeps that screen and its inference contract as Section 5 and adds the adaptation contract around it: a real widget-captioning corpus (one pinned shard of Widget Captioning test widgets, split by app), corpus-level captioning metrics and two non-neural baselines in the carried `metrics.py`, a bounded fine-tuning of the caption decoder, a per-category breakdown, the screen re-captioned after adaptation, and an artifact that reloads. The per-screen `evaluation_report` helper is unchanged; `pipe.evaluate` is the corpus-level stage (`measured` / `measured-small-sample`). The held-out gain is recorded as `adapted_beats_frozen` rather than asserted until a measured recipe is recorded.

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 8-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9, MOD12):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `model.safetensors`), at the pinned revision; `verify_snapshot` re-hashes every entry before `torch` is imported; `Pix2StructWidgetCaptioningPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`) and switches the snapshot's `is_vqa` header path off, so nothing but the blue box is added to the screenshot and no font is fetched. No cell outside the carried modules calls `huggingface_hub`, `transformers`, `pyarrow`, `safetensors` or `urllib`.
- **Data (DAT1–DAT9, ST6):** the default sample is one object in the Hub dataset repository `bevaya/RICO-WidgetCaptioning` at the immutable revision `6ec57b56bebd722b9c646c78d0f34e1199b6d7a9` (`data/test-00000-of-00002.parquet`, 95,313,640 bytes), downloaded whole and refused unless its size and SHA-256 equal the pins in `samples.py`; `fetch_corpus` refuses to run at all while no SHA-256 pin is recorded (`tools/pin_corpus.py` records it from a verified download). Only the screen id, caption, relative box, app-package and screenshot columns are read; widgets are grouped by app, a seeded subset of whole apps is allocated to test, validation and training until each reaches its widget target, and `check_split_disjoint` asserts no shared app and no shared screen.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `check_split_disjoint` + refusal probes (validation) → `validate_inputs` + `pipe.caption` with sanity checks + `keyword_hits` + `evaluation_report` on the drawn screen (inference contract) → `constant_caption_baseline` + `colour_neighbour_baseline` + `pipe.evaluate` on the frozen model with the per-category breakdown (baselines) → `pipe.adapt` (bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `pipe.caption` + `evaluation_report` on the drawn screen again (inference) → `pipe.save_artifact` → `Pix2StructWidgetCaptioningPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the caption is generated text with no score, probability or correctness signal, and the model captions any box, including one around nothing; BLEU-4, ROUGE-L, CIDEr-D and unigram F1 are corpus-level agreement with reference captions (own pure-Python implementations of the `coco-caption` definitions; CIDEr-D's document frequencies come from the evaluated set, so its absolute value is not a leaderboard number); no acceptance threshold ships. The keyword checks on the drawn screen are observations, not a metric.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the constant-caption (corpus medoid) and colour-nearest-neighbour (widget crop) baselines and the frozen model are scored on the same test widgets as the adapted model, on all four metrics and per category; every metric is labelled as one seeded split of one shard with no dispersion estimate.
- **Split integrity (SPL1–SPL8):** the split is seeded and app-disjoint (so screen-disjoint too); validation selects the epoch and the test split is used for nothing but the final evaluation; the notebook states that screens of the same app must never be split apart.
- **Ceilings (VAL6):** `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4096), `MAX_PATCHES` (2048), `MIN_BOX_SIDE` (4), `BOX_COLOR`, `BOX_WIDTH`, `MAX_NEW_TOKENS` (64), `DEFAULT_MAX_NEW_TOKENS` (20), `DECODING`, the record bounds (8..5,000), `MIN_CAPTIONS` (1) and `MAX_CAPTION_CHARS` (200) are stated in the Prerequisites and printed before the model runs; four dataset refusals and one input refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, one zip is read member by member (names flattened, no `extractall`) and its records flow through the same validation, app-disjoint split, baselines, fine-tuning, evaluation, export and reload cells; the training split is written to `outputs/pix2struct_ui_captioning_train.jsonl` in the JSONL shape.
- Licence: the weights are Apache-2.0 and the notebook, README, card and `docs/WEIGHTS.md` say so; the corpus is CC BY 4.0 as declared by the Hub mirror and is not redistributed — the export records its repository, revision, file pin and licence under `corpus`.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
